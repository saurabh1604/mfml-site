   3. Backward Pass — The Two Rules one for each kind of arrow

   THE IDEA


   We want ∂L/∂W and ∂L/∂b for all three layers. Instead of writing L as one giant expression, we
   walk the chain backwards, carrying one thing with us: the gradient of L with respect to the node
   we are standing on.

                              ∂L     ∂L         ∂L         ∂L         ∂L         ∂L
                                  →    (   )
                                             →    (   )
                                                        →    (   )
                                                                   →    (   )
                                                                              →
                              ∂ŷ   ∂z   3     ∂a   2     ∂z   2     ∂a   1     ∂z(1)

   Every arrow we cross backwards converts one of these into the next. There are only two kinds of
   arrow, so there are only two rules.


 STEP S    Where we start

 STEP A    Rule A — crossing a ReLU arrow backwards



The arrow was a = ReLU(z), done element by element. So a j depends on z j and on nothing else — one
term in the chain rule, no sum:

                                        ∂L     ∂L ∂a j     ∂L
                                             =     ·     =      · ReLU′ (z j )
                                        ∂z j   ∂a j ∂z j   ∂a j

Doing that for every j at once is just an element-by-element multiplication:


                          ∂L   ∂L
                             =    ⊙ ReLU′ (z)                (⊙ means multiply entry by entry)
                          ∂z   ∂a
   ReLU′ (z) is a switch: 1 where z was positive, 0 where it was negative. So this rule lets the gradient
   through where the neuron was awake, and blocks it where it was asleep.


 STEP B    Rule B — crossing a linear arrow backwards



The arrow was z = Wa + b. Written out one row at a time:

                                                 z j = ∑ Wjk ak + b j
                                                         k

This arrow gives us three things, because three quantities feed into it.

(i) The gradient of W. The number Wjk sits in one place only — inside z j . One term, no sum:

                                             ∂L    ∂L ∂z j     ∂L
                                                 =     ·     =     ·a
                                            ∂Wjk   ∂z j ∂Wjk   ∂z j k

Entry ( j, k ) is (entry j of a column) × (entry k of a row) — that is an outer product.

(ii) The gradient of b. b j also sits only inside z j , with coefficient 1:

                                                      ∂L     ∂L
                                                           =      ·1
                                                      ∂b j   ∂z j


(iii) The gradient of the layer below. Here ak sits inside every z j , so the chain rule sums:

                                          ∂L     ∂L ∂z j        ∂L
                                              =∑      ·      =∑      Wjk
                                          ∂ak  j
                                                 ∂z j   ∂a k  j
                                                                ∂z j


That sum runs down a column of W, which is a row of W T .


                                ∂L   ∂L T               ∂L   ∂L           ∂L      ∂L
                                   =    a                  =                 = WT
                                ∂W   ∂z                 ∂b   ∂z           ∂a      ∂z
   Forward you multiply by W. Backward you multiply by W T . Same wires, opposite direction.

   ALL FOUR FORMULAS, TOGETHER


                      ∂L                  ∂L    ∂L                       ∂L               T ∂L
                          = ŷ − y           =      ⊙ ReLU′ (z)                 =   W (l )

   THREE THINGS TO REMEMBER


    1. Let the shapes place the transpose. Every gradient has the shape of the thing it belongs to.
       ∂L/∂W (2) must be 2 × 3, so it is (2 × 1)(1 × 3) — there is no other option.

    2. A zero gradient is not a mistake. A sleeping ReLU really does have zero gradient, and its
       weights really do stay put. Too many sleeping at once is the “dying ReLU” problem.
                                                           (1)
    3. Why η had to be so tiny. ∂L/∂W11 = −1800 while ∂L/∂b(3) = −10, because ∂L/∂W (1)
       multiplies by the raw input and age = 30 is large. With η = 10−4 the prediction overshoots
       to 79.3 and the loss rises to 429. The real fix is not a smaller η but scaling the inputs before
       training.

   THE WHOLE ALGORITHM


   Forward: a(0) → z(1) → a(1) → z(2) → a(2) → z(3) → ŷ → L, storing every node.
   Backward: start with ∂L/∂ŷ = ŷ − y, then walk back across the arrows: ReLU arrow ⇒ ∂L/∂z =
   ∂L/∂a ⊙ ReLU′ (z); linear arrow ⇒ ∂L/∂W = ∂L/∂z aT , ∂L/∂b = ∂L/∂z, ∂L/∂a = W T ∂L/∂z.
   Update: θ ← θ − η ∂L/∂θ.                  Repeat.
